# 研究和学习计划

> 本文档包含两条并行推进的主线：**项目计划**（做什么）与**学习曲线**（学什么）。两者同步进行、相互支撑——学习为项目提供能力基础，项目为学习提供验证场景。

## 一、项目计划

整体推进思路：**先验证 RT 稀疏化是否有效，再验证理想调度上限，最后引入神经网络**，而不是一开始就进入模型训练。

### 1. 第一阶段：实验 A——RT Sparsity Test（验证 RT 稀疏化）

**目的：** 在不引入 AI 的前提下，确认 SSR-Guardian 最基本的工程假设——减少 RT rays 能否真正转化为显著的 Frame Time 降低，以及不同 GPU 瓶颈条件下这种收益是否存在明显差异。

**做法：** 在相同场景与渲染条件下，分别对 100%、50%、20%、10%、5% 乃至 1% 的像素或 tile 执行光线追踪，并通过 GPU profiling 分析 RT Core、SM、显存访问、DXR Dispatch、同步等环节的耗时变化。

**产出与判断：** 得到"RT 工作量与实际帧时间之间的关系曲线"。若 RT 稀疏化能稳定带来帧时间下降，则该方向成立，可进入下一阶段；若收益受瓶颈限制明显，则需优先定位瓶颈原因。

### 2. 第二阶段：实验 B——Oracle Scheduler（验证理想调度上限）

**目的：** 用理想化的"完美调度器"回答一个关键问题——有限 RT Budget 本身究竟能带来多少视觉改善，从而判断问题是否具备足够的稀疏性。

**做法：** 利用离线生成的 SSR 与高质量 RT 结果，直接计算每个区域接受 RT 修复后能获得的真实视觉收益，再按收益从高到低分配 RT Budget（如 5%、10%、20%），只对收益最高的区域执行 RT。

**预期与判断：** 若 Oracle Scheduler 在很低的 RT Budget 下就能接近 Full RT 的视觉效果，说明方向潜力很大，值得引入神经网络；若即使拥有完美调度仍需要大量 RT 才能明显改善画面，则说明问题稀疏性有限，需要调整方案。

### 3. 第三阶段：实验 C——Neural Scheduler（用网络逼近理想调度）

**前提：** 前两个阶段已分别验证 RT 稀疏化有效、且存在明确的理论收益上限，此时再引入神经网络。

**做法：** 让轻量级模型学习逼近 Oracle Scheduler 的决策结果。输入可逐步加入 Depth、Normal、Roughness、SSR、Motion Vector 和历史帧信息，输出 Error Probability、RT Benefit 或综合 Priority Score。

**扩展方向：** 在此基础上逐步研究 Temporal Prediction、Geometry-aware Label、GPU-side Ray Compaction、TensorRT/TensorRT-RTX、异步 Compute 等机制，使神经网络最终真正成为实时渲染管线中的低开销智能调度器。

## 二、学习曲线

学习节奏与项目开发同步推进，而不是先完成大量课程学习后再开始项目。整个学习过程按以下五个阶段递进。

### 1. GPU 与 DX12 基础（建立性能直觉）

**内容：** 现代 GPU 的执行模型、SM、Warp/Wave、Cache、Memory Bandwidth、Occupancy、Branch Divergence 等概念，以及 DirectX 12 的 Command Queue、Command List、Resource State、Barrier、Fence、Descriptor 等机制。

**目标：** 建立对 GPU 程序性能的基本直觉。

### 2. DXR 实时光追（理解"光追为什么贵"）

**内容：** BLAS、TLAS、BVH Traversal、Ray Generation、Hit/Miss Shader、Shader Binding Table 等概念，并通过一个规模较小的 DXR Demo，走通一条 Ray 从生成到最终着色的完整流程。

**目标：** 能够解释实时光追昂贵的原因，以及不同类型的 RT workload 为何会受不同硬件单元的限制。

### 3. GPU 性能分析（从"怎么写"转向"为什么慢"）

**内容：** 使用 PIX、Nsight Graphics 等工具进行实际 profiling，识别 RT-bound、SM-bound、Memory-bound、Cache 问题、Divergence、CPU-GPU Synchronization 等典型瓶颈。

**目标：** 学会判断一个 GPU 程序为什么慢，而不只是会写 GPU 程序。

### 4. TensorRT 与 Tensor Core（把轻量模型放进实时管线）

**内容：** FP16、Tensor Core、TensorRT Engine、GPU Memory Binding、数据预处理、异步推理、Inference Latency 等。重点不是训练大型神经网络，而是理解如何把轻量模型融入实时图形管线。

**重点关注：** 数据转换与同步开销是否会抵消神经网络本身带来的低计算成本。

### 5. 综合优化（端到端 Pipeline 优化）

**内容：** 将 DX12、DXR、GPU Profiling、TensorRT 与调度算法真正结合，研究 GPU-side preprocessing、Ray Compaction、ExecuteIndirect、Async Compute、Resource Management 以及减少同步开销等问题。

**目标：** 将优化视角从单个模块提升到整个实时渲染 Pipeline 的端到端优化。

## 三、十个月主线

整个十个月的主线可以概括为：

> **GPU 基础 → DX12 → DXR → GPU Profiling → RT Sparsity → Oracle Scheduler → TensorRT/Tensor Core → Neural Scheduler → GPU Pipeline 综合优化**

这条主线的核心优势在于"能力沉淀"：即使最终 Neural Scheduler 没有达到最初设想的收益，前期积累的 DX12、DXR、GPU profiling、GPU memory、shader optimization 和 TensorRT 等能力，依然可以独立形成具有就业价值的 GPU 工程能力。
